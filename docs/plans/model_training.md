# План за обучение на AI модели — AquaSense

## Контекст

Имаме 5 CSV файла от CMEMS за Бургаски залив / о. Света Анастасия:

| Файл | Редове | Период | Параметри |
|---|---|---|---|
| `temperature.csv` | 570 | 2022-06-01 → 2023-12-22 | temperature_C |
| `sea_level.csv` | 1086 | 2021-01-01 → 2023-12-22 | sea_level_m |
| `salinity.csv` | 1086 | 2021-01-01 → 2023-12-22 | salinity_psu |
| `o2.csv` | 366 | 2022-06-01 → 2023-06-01 | dissolved_o2, primary_production |
| `nutrients.csv` | 570 | 2022-06-01 → 2023-12-22 | nitrate, phosphate |
| `burgas_final.csv` | 370 | 2022-06-01 → 2023-06-01 | всички обединени |

## Стъпка 1 — Подготовка на данните (`prepare_data.py`)

### 1.1 Конвертиране на единици

- `dissolved_o2`: mmol/m³ → mg/L чрез умножение по **0.032**
- `temperature_C`: вече е в °C ✅
- `sea_level_m`: вече е в метри ✅
- `salinity_psu`: вече е в PSU ✅

### 1.2 Синтетични параметри

Нямаме реални данни за **pH** и **мътност** от CMEMS. Генерираме ги реалистично:

**pH** (емпирична формула за Черно море):
```
pH ≈ 8.2 − 0.01 × (temperature_C − 20) + 0.005 × (salinity_psu − 18)
```

**Мътност (NTU):**
```
turbidity ≈ 15 NTU базова стойност + случаен шум + пикове при бури
```

### 1.3 Нормализация

- Всички числови колони се нормализират към диапазон **[0, 1]** с `MinMaxScaler`
- Скейлърът се запазва като `scaler.pkl` — нужен е при inference на Raspberry Pi 5 за обратно конвертиране

### 1.4 Изходни файлове

- `docs/processed/prepared_data.csv` — финален почистен dataset за двата модела
- `docs/processed/scaler.pkl` — запазен скейлър

## Стъпка 2 — Isolation Forest (`train_isolation_forest.py`)

### Какво прави

Учи се на "нормалното" разпределение на данните и маркира точки, които статистически се отклоняват — без нужда от предварително етикетирани аномалии.

### 2.1 Входни данни

- Файл: `burgas_final.csv` (370 реда)
- Колони: всички без `time`
- Не се разбърква и не се разделя — unsupervised learning използва целия dataset

### 2.2 Хиперпараметри

```python
contamination = 0.05   # приемаме че ~5% от данните са аномалии
n_estimators  = 200    # брой дървета
random_state  = 42
```

### 2.3 Обучение

Моделът се обучава на нормализираните данни. Всяка точка получава **anomaly score** — колкото по-отрицателен, толкова по-вероятна е аномалията.

### 2.4 Прагове за аларми (от документацията на проекта)

| Параметър | Тревожна стойност |
|---|---|
| Температура | > 28 °C |
| pH | < 6.5 или > 9.0 |
| Мътност | > 60 NTU |
| Разтворен O2 | < 4 mg/L (хипоксия) |
| Водно ниво | > 30 cm/h покачване |

### 2.5 Валидация

Ръчно проверяваш 5–10 от маркираните аномалии — дали съвпадат с реални екологични събития в Черно море за периода 2022–2023 (търси в EMODnet или научни публикации).

### 2.6 Запис

```
models/isolation_forest.pkl
```

## Стъпка 3 — LSTM (`train_lstm.py`)

### Какво прави

Рекурентна невронна мрежа, която учи времеви модели и предсказва бъдещи стойности с хоризонт **24 часа (1 ден) напред**.

### 3.1 Входни данни

Използваме по-дългите отделни файлове за по-добро обучение:
- Основно: `sea_level.csv` + `salinity.csv` (по 1086 реда)
- После добавяме останалите с merge_asof

### 3.2 Windowing (създаване на прозорци)

LSTM не получава целия dataset наведнъж — получава последователности:

```
lookback_window  = 30  # вижда последните 30 дни
forecast_horizon = 1   # предсказва следващия ден
```

От 1086 реда се получават **~1056 тренировъчни примера** — достатъчно за малка мрежа.

### 3.3 Разделяне на данните

| Сет | Дял | Редове | Период |
|---|---|---|---|
| Train | 80% | ~845 | първите редове |
| Validation | 10% | ~105 | средните редове |
| Test | 10% | ~105 | последните редове |

> ⚠️ **Не разбъркваш данните** — времевият ред трябва да се запази.

### 3.4 Архитектура на мрежата

```
Input(30, n_features)
    → LSTM(64, return_sequences=True)
    → Dropout(0.2)
    → LSTM(32)
    → Dropout(0.2)
    → Dense(n_features)
Output(1, n_features)
```

Малка мрежа — при 370–1086 реда голяма мрежа ще се преобучи (overfitting).

### 3.5 Параметри на обучението

```python
epochs      = 50
batch_size  = 16
optimizer   = 'adam'
loss        = 'mse'
early_stopping = patience=10  # спира ако val_loss не се подобрява
```

### 3.6 Валидация

- Сравняваш предсказаните стойности с реалните от test set-а
- Цел: **MAE < 5%** от обхвата на всеки параметър
- Визуализираш predicted vs actual с matplotlib

### 3.7 Запис

```
models/lstm_model.keras
models/scaler.pkl       # същият от Стъпка 1
```

## Стъпка 4 — Комбиниране на моделите (`validate_models.py`)

В реалната система на Raspberry Pi 5 двата модела работят заедно при всяконово сензорно измерване:

```
Ново измерване от ESP32
        ↓
┌───────────────────────────────────────┐
│  Isolation Forest                     │
│  → Аномалия? (anomaly score < праг)   │
└───────────────────────────────────────┘
        ↓
┌───────────────────────────────────────┐
│  LSTM                                 │
│  → Предсказва следващата стойност     │
│  → Отклонение от реалното > праг?     │
└───────────────────────────────────────┘
        ↓
   И двете → 🔴 ВИСОКА АЛАРМА
   Само едното → 🟡 ПРЕДУПРЕЖДЕНИЕ
   Нито едното → 🟢 НОРМАЛНО
```

## Стъпка 5 — Симулация за хакатона (`simulate_anomaly.py`)

Тъй като на острова нямаме 24 часа реални данни за демото, симулираме inference:

1. Вземаш последните 30 реда от test set-а
2. Подаваш ги на LSTM → получаваш прогноза за следващия ден
3. Инжектираш изкуствена аномалия (напр. O2 спада до 2 mg/L)
4. Isolation Forest я засича → алармата светва на dashboard-а
5. Three.js сцената се оцветява в червено
